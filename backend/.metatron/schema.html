Omega Schema

Every entity in the codebase with its real columns, and every reference between them. Declaring a relation to the ORM couples two contexts, so many are stored as a bare id column instead — those still exist, they are just invisible to the ORM. Both kinds are drawn here.

01

Declared and implicit

A declared reference is a TypeORM relation decorator: the ORM knows about it, can join through it, and will generate a foreign key. An implicit one is a plain someId column that happens to hold another table's primary key. The database has no constraint, the ORM cannot join it, and no schema tool will draw it — but the dependency is just as real, and application code has to honour it by hand.

How references were found

Declared ones are read from @ManyToOne, @OneToMany, @OneToOne and @ManyToMany decorators. Implicit ones are inferred from column names: a column ending Id or _id whose stem matches an entity class or table name, singular or plural. parentId is read as a self-reference.

Where a relation is written both ways — the decorator plus the id column beside it — that is one relationship, and it is folded into a single declared edge keeping the column name. An id column that matches no entity is not guessed at: a stripeCustomerId naming something outside the codebase is left alone rather than invented.
